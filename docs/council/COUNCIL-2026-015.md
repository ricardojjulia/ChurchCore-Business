## I. Executive Summary

The High Sovereign Grand Council of ChurchCore formally establishes **OpenRouter (`https://openrouter.ai/api/v1`)** as the universal default provider for all LLM and generative AI capabilities across the entire ChurchCore software suite. 

To ensure institutional sustainability, sub-50ms Sunday morning responsiveness, and uncompromising accuracy, this directive mandates an algorithmic operating layer between user workloads and model execution:
1. **Zero Direct Vendor Lock-in**: Single unified gateway avoiding proprietary SDK sprawl.
2. **Mandatory Zero Data Retention**: Every payload must enforce `"provider": { "data_collection": "deny" }`.
3. **Multi-Dimensional Balanced Routing**: Tasks are dynamically scored across Truthness/Reasoning vs Usability/Latency/Cost.
4. **Deterministic Semantic / SHA-256 Prompt Caching**: Immediate `<5ms` returns for identical governance, invariant, and classification inquiries, saving token overhead.
5. **Context Window Compaction**: Trimming formatting and whitespace noise while strictly preserving constitutional constraints.
6. **Active Model Radar**: Continuous evaluation of newly released frontier models (e.g., Gemini 2.5 Pro/Flash, Claude 3.7 Sonnet, DeepSeek R1, Llama 3.3) to capture pricing drops and capability leaps automatically.

## II. Ratified Technical Requirements

### `REQ-015-01`: OpenRouter Default Fleet AI Provider Standard
All generative AI workloads across ChurchCore packages MUST route requests through OpenRouter (`https://openrouter.ai/api/v1/chat/completions`) using the standardized request headers:
- `Authorization: Bearer ${OPENROUTER_API_KEY}`
- `HTTP-Referer: https://churchcore.io`
- `X-Title: ChurchCore Sovereign Fleet`
- `provider: { data_collection: "deny" }` (Strict Zero Data Retention)

Direct proprietary SDK vendor bindings (e.g. `@google/genai`, direct OpenAI or direct Anthropic SDKs) that bypass this privacy and routing policy are prohibited.

### `REQ-015-02`: Multi-Dimensional Balanced Routing Algorithm
Workloads MUST be evaluated and categorized into one of three operational tiers:
- **Tier 1 (Truthness & Deep Reasoning)**: High-stakes governance, constitutional invariant verification, theological fidelity, and safeguarding audits. Default: `google/gemini-2.5-pro` (Failover: `google/gemini-2.5-flash` or `anthropic/claude-3.7-sonnet`).
- **Tier 2 (Balanced Generative Workhorse)**: General reporting, editorial drafting, localization/translation, and interactive pastoral aids. Default: `google/gemini-2.5-flash` (Failover: `meta-llama/llama-3.3-70b-instruct`).
- **Tier 3 (Ultra-Fast Micro-Latency)**: High-throughput classification, triage tags, sentiment scoring, and routing. Default: `google/gemini-2.5-flash-lite` (Failover: `meta-llama/llama-3.1-8b-instruct`).

### `REQ-015-03`: SHA-256 Prompt Caching & Token Optimization
The OpenRouter operating software MUST implement an in-memory or KV semantic cache:
- Computes SHA-256 fingerprint: `sha256(taskType + model + systemPrompt + userPrompt)`.
- Enforces task-specific TTLs (15 min for deliberations, 1 hr for marketing/invariants, 24 hr for translations/tags).
- Applies automated prompt compaction to eliminate whitespace and formatting overhead before dispatching.
- Cache hits return in `<5ms` with zero token consumption and record cost savings telemetry.

### `REQ-015-04`: Active Model Radar & Feature Discovery Engine
The control plane MUST provide continuous discovery via `https://openrouter.ai/api/v1/models`:
- Automatically parses newly added models, token pricing, context window limits, and capability tags.
- Computes a balanced fitness score ($Score = 0.55 \cdot Truthness + 0.45 \cdot Efficiency$).
- Flags models released in the last 90 days as `"Newly Released"`.
- Exposes real-time model recommendations via `/api/openrouter/models` and the control room dashboard.
