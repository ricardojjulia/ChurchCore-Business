## 1. Executive Summary & Intent

By unanimous determination of the High Sovereign Grand Council on October 20, 2026, the **Universal Localization Governance & OpenRouter Translation Standard** is hereby ratified as a fleet-wide technical directive.

Following an exhaustive architectural audit of localization and internationalization systems across all six product repositories, the Council determined that **`ChurchCore Care`'s `@localization-governance` framework** represents the gold standard for enterprise translation management. Effective immediately, this architecture is extracted, canonized, and mandated as the standard translation engine for the entire ChurchCore ecosystem.

### 1.1 The Operational Deficiencies Eliminated
Prior to this directive, individual packages utilized fragmented and fragile translation approaches:
1. **Placeholder Token Corruption**: Machine translation APIs and third-party tools frequently translated or dropped interpolation tokens (e.g. converting `{userName}` to `{nombreDeUsuario}`), resulting in fatal React hydration mismatches and client-side crashes in Spanish and Portuguese locales.
2. **Untracked Production Drift**: New English UI keys were committed without corresponding target language entries, leaving users with jarring bilingual interfaces and raw i18n keys (`errors.auth.invalid_token`) in live production.
3. **Theological, Clinical, and Legal Term Drift**: Generic translation models substituted colloquial or secular words for carefully vetted denominational, pastoral counseling, and statutory terms.
4. **Lack of Lifecycle Governance**: Raw automated translations were pushed directly to production without staging, linguistic review, or verified approval states.

### 1.2 The Sovereign Standard
Effective immediately:
1. **Universal Governance Toolkit**: All packages must adopt the framework-neutral **`@localization-governance`** core state machine (`draft` $\rightarrow$ `review` $\rightarrow$ `approved` $\rightarrow$ `activated` $\rightarrow$ `stale`).
2. **OpenRouter AI Translation Gateway**: Per `COUNCIL-2026-010`, all automated catalog translation generation must route through **OpenRouter** utilizing Tier 2 high-efficiency models (`google/gemini-2.5-flash` or `meta-llama/llama-3.3-70b-instruct`) with mandatory Zero Data Retention (`data_collection: "deny"`).
3. **Strict Placeholder Invariant**: CI/CD pipelines must strictly enforce regex token preservation (`/\{(\w+)\}/g`), failing builds if target placeholders diverge from canonical source keys.
4. **Mandatory Domain Glossaries**: Each package must enforce an application-specific glossary (`data/glossaries/<locale>.json`) protecting confessional credos, clinical terms, SIS records, and financial ledger phrasing.

## 2. Technical Requirements

### REQ-011-01: Enterprise `@localization-governance` Framework Adoption
All application repositories must integrate the standardized `@localization-governance` modules (originally developed in `ChurchCore Care`):
- **Core State Engine (`@localization-governance/core`)**: Manages locale lifecycle, atomic versioned activations, rollback safety, and coverage calculations (capped strictly at 100% of canonical source keys).
- **Storage Adapters**:
  - *Filesystem Adapter (`@localization-governance/storage-filesystem`)*: For compile-time static UI dictionaries and edge client bundles.
  - *PostgreSQL Adapter (`@localization-governance/storage-postgres`)*: For database-backed tenant overrides and live admin translations with constitutional Row-Level Security (RLS).
- **Command-Line Interface (`@localization-governance/cli` / `locgov`)**: Standardized CLI for catalog inspection, validation, and export.
* **Verification:** Presence of `@localization-governance/core` and `localization-governance.config.mjs` in each application package.

### REQ-011-02: OpenRouter AI Translation Gateway Integration
In compliance with Directive `COUNCIL-2026-010`, all machine-assisted catalog translation workflows must route exclusively through OpenRouter:
- **Provider Adapter:** `@localization-governance/provider-openrouter` (or `ops/translate-locale.mjs`).
- **Endpoint:** `https://openrouter.ai/api/v1/chat/completions` using `OPENROUTER_API_KEY`.
- **Target Tier:** Tier 2 High Efficiency (`google/gemini-2.5-flash` or `meta-llama/llama-3.3-70b-instruct`).
- **Zero-Retention Header:** Mandatory `"data_collection": "deny"`, `HTTP-Referer: https://churchcore.io`, and `X-Title: ChurchCore Localization Engine`.
* **Verification:** Automated translation requests produce verified OpenRouter traces with zero raw proprietary vendor SDK lock-ins.

### REQ-011-03: Variable Token `{var}` Preservation & Domain Glossaries
1. **Regex Placeholder Guard:** Translation utilities must parse source strings for placeholder tokens (`/\{(\w+)\}/g`). Any translation that alters, omits, or adds a placeholder token must be rejected at validation time.
2. **Domain Glossary Mandate:** Each application package must maintain a versioned domain glossary in `data/glossaries/<locale>.json`:
   - **ChurchCore (ChMS):** Tithing, fund accounting, double-entry ledgers, deaconate, children's check-in PINs.
   - **ChurchCore Care:** Pastoral counseling, HIPAA confidentiality, spiritual intake, SOAP notes, crisis triage.
   - **ChurchCore-LMS:** Ministerial credentials, course modules, syllabi, rubrics, AETH certification.
   - **ChurchCore-Academy:** Gradebooks, attendance, tuition schedules, FERPA records, academic transcripts.
   - **ChurchCore-Orthos:** Denominational bylaws, background check clearances, safeguarding audits.
   - **FaithFullScholars:** Confessional credos, peer-reviewed monographs, DOI citations, faculty tenure dossiers.
* **Verification:** `locgov validate` reports zero placeholder mismatches and zero rejected glossary terms.

### REQ-011-04: Mandatory Pre-Merge CI Quality Gate
Every application package must expose a standard npm script in `package.json`:
```json
"scripts": {
  "audit:i18n": "node ops/translate-locale.mjs --review"
}
```
And enforce this check in GitHub Actions CI workflows (`.github/workflows/ci.yml`). Any pull request that introduces missing translation keys, blank strings, placeholder mismatches, or glossary violations must fail closed before merge.
* **Verification:** Execution of `npm run audit:i18n` exits with code 0 on all clean repositories and halts PR builds on corrupted catalogs.
