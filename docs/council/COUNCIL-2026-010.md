## 1. Executive Summary & Intent

By unanimous decree of the High Sovereign Grand Council in Plenary Session on October 19, 2026, the **Universal AI Gateway Consolidation and Model Evaluator Standard** is hereby ratified as a permanent architectural and commercial requirement across all ChurchCore product packages.

### 1.1 The Strategic Problem Solved
Prior to this directive, individual sibling repositories risked architectural fragmentation by introducing ad-hoc SDK integrations with disparate AI vendors (e.g. direct raw OpenAI SDK, direct Anthropic SDK, local mock endpoints). This fragmentation produced:
1. **Uncontrolled Cloud Spend**: Unbounded token consumption without central budget ceilings or rate controls.
2. **Vendor Lock-In & Outage Vulnerability**: Hardcoded model identifiers that fail closed during proprietary provider outages instead of failing over to contending alternatives.
3. **Imbalanced Model Selection**: Using expensive frontier reasoning models for trivial string formatting, or conversely, using low-parameter models for mission-critical theological, safeguarding, or legal compliance checks where truthness and doctrinal accuracy are paramount.
4. **Data Sovereignty Violations**: The risk that church member confidential data, clinical pastoral counseling notes, or child safety records could be ingested into public model training corpuses without strict zero-retention flags.

### 1.2 The Sovereign Mandate
Effective immediately:
1. **Single Unified AI Gateway**: All software packages across the ChurchCore fleet **MUST route 100% of LLM calls exclusively through OpenRouter** (`https://openrouter.ai/api/v1/chat/completions`) using the standardized `OPENROUTER_API_KEY`. Direct vendor SDK bindings (raw `openai`, `@anthropic-ai/sdk`) are strictly prohibited in production runtimes.
2. **Model Usage & Model Evaluator Protocol**: Every package must implement an **Intelligent Model Evaluator** that dynamically balances **Truthness & Accuracy** against **Efficiency, Latency, and Cost Sustainability**. Frontier reasoning models may not be leveraged without justifiable classification and cost constraints.

## 2. Technical Requirements

### REQ-010-01: Universal OpenRouter Gateway Consolidation
All external AI requests across backend API routes, edge serverless functions, and scheduled cron jobs must target the OpenRouter API gateway:
- **Base Endpoint:** `https://openrouter.ai/api/v1/chat/completions`
- **Mandatory Environment Variable:** `OPENROUTER_API_KEY`
- **Mandatory Identification Headers:**
  - `HTTP-Referer`: `https://churchcore.io` (or package canonical production URL)
  - `X-Title`: `ChurchCore <Product Suite Name>` (e.g., `ChurchCore ChMS`, `ChurchCore Care`)
- **Privacy Standard:** Requests must specify `data_collection: "deny"` to ensure church member data is never utilized for LLM fine-tuning or model training.
* **Verification:** Zero unauthorized third-party AI provider base URLs in production codebases; authenticated OpenRouter HTTP dispatch tested and verified.

### REQ-010-02: Sovereign Model Evaluator & Dynamic Tier Routing
Every application package must incorporate a centralized `model_evaluator` module (e.g., `lib/ai/model-evaluator.ts` or `src/ai/evaluator.py`) that scores incoming prompt workloads and dynamically routes to the optimal model tier:

#### The Evaluator Quadrant:
1. **Tier 1: High Truthness & Complex Reasoning (High Fidelity)**
   - *Use Cases:* Theological dispute adjudication, child safeguarding risk analysis, clinical pastoral care triage, complex gradebook calculation audits, canonical compliance verification, and Section III Data Sovereignty checks.
   - *Default Recommended Models:* `google/gemini-2.5-pro`, `anthropic/claude-3.5-sonnet`, `deepseek/deepseek-r1`.
   - *Constraint:* Requires explicit high-priority tag or council governance escalation. Cannot be used for background loop poller tasks.

2. **Tier 2: High Efficiency & Sustainable Utility (Balanced Workhorse)**
   - *Use Cases:* Sunday morning live bulletin drafting, sermon transcription summarization, attendance alert phrasing, email notifications, volunteer role matching, query expansion, and general administrative assistance.
   - *Default Recommended Models:* `google/gemini-2.5-flash`, `meta-llama/llama-3.3-70b-instruct`, `mistralai/mistral-large-2411`.
   - *Constraint:* Sub-second time-to-first-token; optimized for high-throughput Sunday peak workloads.

3. **Tier 3: Ultra-Low-Cost Fast Triage (High Throughput / Micro-Tasks)**
   - *Use Cases:* Search intent classification, entity extraction from incoming member notes, tag categorization, syntax validation, sentiment categorization.
   - *Default Recommended Models:* `google/gemini-2.5-flash-lite`, `meta-llama/llama-3.1-8b-instruct`.
   - *Constraint:* Negligible cost profile ($0.05–$0.15 per million tokens).

* **Verification:** Unit tests confirming that low-complexity tasks resolve to Tier 2/3 and that high-truthness tasks resolve to Tier 1 with fallback cascades.

### REQ-010-03: Cost & Sustainability Guardrails
To prevent runaway consumption and safeguard church operational budgets:
1. **Per-Request Token Caps:** Every prompt must specify explicit `max_tokens` bounded by task complexity.
2. **Automatic Fallback Cascades:** Requests to OpenRouter must pass an ordered list of fallback models (e.g., `models: ["google/gemini-2.5-pro", "anthropic/claude-3.5-sonnet", "google/gemini-2.5-flash"]`) to guarantee 99.99% Sunday availability without vendor downtime.
3. **Token Usage Audit Logging:** Packages must record prompt tokens, completion tokens, model utilized, and latency in telemetry or local telemetry logs.
4. **Circuit Breakers:** If an individual tenant or anonymous session attempts more than 100 requests/hour, the evaluator must downgrade to Tier 3 or return rate-limit advisories.

## FaithFull Scholars adoption record (2026-10-20)

FaithFull Scholars adopted REQ-010-01 on the terms of its 2026-10-20 challenge (`docs/council/CHALLENGE-2026-10-20-faithfull-scholars.md`, challenge 5): a per-product ADR plus a privacy review, with no deadline. The owner decided the details.

- **Gateway:** the AI faculty matcher calls only `https://openrouter.ai/api/v1/chat/completions` with `OPENROUTER_API_KEY`. Direct Google calls and `GEMINI_*` variables are removed, and a unit test fails if either returns (FaithFull PR #104, `9e9725f`; ADR 0041).
- **Privacy, stricter than this directive's `data_collection: "deny"`:** every request carries `provider: { zdr: true, data_collection: "deny" }`, so only zero-data-retention endpoints serve it. With no qualifying endpoint, the request is refused and a built-in heuristic answers.
- **Model:** `google/gemini-2.5-flash`. Only `google/gemini-*` models are allowed, because the privacy policy names Google as the model provider.
- **Legal:** Privacy Policy v4 and belief-consent text v2 name OpenRouter and Google. Migration `20261020090000` was applied to production 2026-10-20 (Release #27).
- **Update 2026-10-26: REQ-010-02 and REQ-010-03 adopted** (FaithFull PR #132, `6241d2c`; ADR 0041 amendment; Council Review 43). `lib/ai/model-evaluator.ts` routes registered tasks to Gemini-only tiers (Tier 1 `gemini-2.5-pro` on explicit escalation only, unused; Tier 2 `gemini-2.5-flash` for the faculty matcher; Tier 3 `gemini-2.5-flash-lite`); unknown tasks are refused. Guardrails: per-task `max_tokens` (matcher 4000), an ordered `models` fallback cascade of at most 3 Gemini models that only steps down in cost, a served model outside the allowlist is refused, and one content-free `ai_gateway_call` log line per request (task, tier, model, provider, tokens, finish_reason, latency, status). Rate limits fail closed (PR #131: 10/hour per person, 50/day per institution, staff 30/hour), stricter than this directive's 100/hour circuit breaker. Deviations: Gemini only (privacy policy names Google), no Tier-1 'credo theological alignment' (owner decision: the matcher makes no doctrinal judgement; PR #131), usage logged to Vercel logs.
- **Also removed:** two never-wired Gemini helpers (the CV extractor and syllabus tagger). This directive's "monograph semantic analysis" use case does not exist in FaithFull.
