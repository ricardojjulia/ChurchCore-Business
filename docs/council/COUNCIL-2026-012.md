## 1. Context & Problem Statement

Historically, the **ChurchCore Sovereign Control Plane (`ChurchCore-Business`)** operated via a local Python HTTP daemon (`dashboard/serve.py` on port `3333`) backed by flat JSON files (`dashboard/fleet-data.json`, `dashboard/feedback-data.json`, `dashboard/presos-data.json`) and local filesystem polling.

While effective during initial bootstrapping, a live operational incident on October 28, 2026 demonstrated four structural limitations of the local-only daemon architecture:
1. **Single-Host Availability Risk:** Long-lived local Python processes (`serve.py`) can wedge on stale TCP socket descriptors (`Empty reply from server`), rendering Executive Mission Control unreachable until manually restarted on the operator's workstation.
2. **Absence of Cryptographic Operator Authentication:** The local cockpit lacked an identity gate, leaving executive deliberation endpoints (`/api/deliberate`, `/api/marketing-ai`, `/api/feedback-council`), OPEX sensitivity models, and directive dispatch controls unauthenticated if exposed beyond loopback.
3. **Manual & Git-Noisy Telemetry Synchronization:** Synchronizing edge telemetry required either a running local background thread or manual script execution that mutated tracked JSON/JS files in the repository working tree.
4. **Blueprint Dogfooding Mandate:** Under [`docs/control-plane/EMBEDDED-SECURITY-ARCHITECTURE.md`](../control-plane/EMBEDDED-SECURITY-ARCHITECTURE.md), the Control Plane mandates Next.js 16 App Router embedded security guardrails (`createProtectedAction`, constant-time `CRON_SECRET` validation, cryptographic webhook verification, token-bucket AI rate limiting, and 100% forced PostgreSQL Row-Level Security). The Control Plane itself must serve as the **Baseline Reference Implementation** of this architecture.

## 3. Strategic & Technical Specifications (Mandatory Requirements)

### `REQ-012-01`: Next.js 16 App Router & Embedded Security Guardrails
`ChurchCore-Business` shall implement a Next.js 16 (App Router) + TypeScript application enforcing the contracts in [`docs/control-plane/EMBEDDED-SECURITY-ARCHITECTURE.md`](../control-plane/EMBEDDED-SECURITY-ARCHITECTURE.md):
- `src/types/security.ts`: Standardized `SecurityErrorCode`, `SecurityErrorDetail`, and `ActionResponse<T>` discriminated union.
- `src/lib/security/action-wrapper.ts`: `createProtectedAction` higher-order server action wrapper with Zod schema validation, Vercel edge IP resolution (`x-vercel-ip` priority), local WASM/signature threat inspection (SQLi, XSS, path traversal, command injection), and sliding-window/token-bucket rate limiting.

### `REQ-012-02`: Username/Password Authentication Gate & Allowlisted Operator RBAC
All executive cockpit routes (`/`, `/api/deliberate`, `/api/marketing-ai`, `/api/feedback-council`, `/api/tasks`, `/api/sync-telemetry`) shall be gated behind authentication:
- Dedicated `/login` screen with username/email + password authentication (supporting Supabase Auth SSR session cookies alongside cryptographically signed HMAC-SHA256 operator sessions backed by `CONTROL_PLANE_ADMIN_USERNAME` / `CONTROL_PLANE_ADMIN_PASSWORD_HASH` for zero-downtime local/edge failover).
- Next.js Middleware (`src/middleware.ts`) enforcing fail-closed redirects to `/login` for unauthenticated browser requests and `HTTP 401 Unauthorized` for unauthenticated API mutations.

### `REQ-012-03`: Constitutional Section III Supabase Schema & 100% Forced RLS
The Control Plane PostgreSQL migration (`supabase/migrations/20261028000000_control_plane_governance_schema.sql`) shall define:
1. `public.control_plane_operators` (Allowlisted operator accounts & roles)
2. `public.fleet_telemetry_snapshots` (Immutable & latest edge telemetry records per product pillar)
3. `public.governance_tasks` (Cross-portfolio Kanban tasks & priority queue)
4. `public.council_deliberations` (Ratified Dual-Contending Gemini council transcripts & prompts)
5. `public.demo_feedback_entries` (Stakeholder demo feedback & error-triage items)
6. `public.sync_execution_logs` (Audit trail of Vercel Cron, GitHub Webhook, and manual telemetry syncs)
- Every table MUST execute `ALTER TABLE ... ENABLE ROW LEVEL SECURITY;` and `ALTER TABLE ... FORCE ROW LEVEL SECURITY;` with explicit `DENY-ALL` default posture for `anon` and strict `public.is_control_plane_operator()` policies for `authenticated`.
- Every `SECURITY DEFINER` function MUST pin `SET search_path = public`.

### `REQ-012-04`: Constant-Time Vercel Cron & Cryptographic GitHub Webhook Mesh
- `src/app/api/cron/fleet-sync/route.ts`: Scheduled via `vercel.json` (`*/15 * * * *`). Validates `Authorization: Bearer <CRON_SECRET>` using constant-time `crypto.timingSafeEqual`. Fetches published `main` telemetry (`docs/control-plane/telemetry.json`) and roadmaps (`docs/mvp-100-plan.md`) from GitHub across all 6 repositories, runs non-mutating live HTTP availability probes (`REQ-008-02` compliant), and persists snapshots to Supabase (with local fallback).
- `src/app/api/webhooks/github/route.ts`: Validates `x-hub-signature-256` using HMAC-SHA256 and `crypto.timingSafeEqual` against `GITHUB_WEBHOOK_SECRET`. Automatically triggers targeted product telemetry & plan refresh on `push` or merged `pull_request` events.

### `REQ-012-05`: Full Ecosystem Dogfooding (`COUNCIL-2026-002`, `010`, `011`)
- **Brand House (`COUNCIL-2026-002`):** Renders the canonical `Powered by ChurchCore` trust badge on `/login` and the main cockpit footer (`src/components/branding/ChurchCoreTrustBadge.tsx`).
- **OpenRouter AI Gateway (`COUNCIL-2026-010`):** Consolidates all LLM calls in `src/lib/ai/openrouter-gateway.ts` through `https://openrouter.ai/api/v1/chat/completions` with `"data_collection": "deny"`, dynamic 3-tier Sovereign Model Evaluator routing, `max_tokens <= 4096`, and fallback cascade chains.
- **Localization Governance (`COUNCIL-2026-011`):** Includes `localization-governance.config.mjs`, `ops/translate-locale.mjs`, `data/glossaries/es.json`, and validated `locales/en.json` + `locales/es.json` catalogs verified via `npm run audit:i18n`.
