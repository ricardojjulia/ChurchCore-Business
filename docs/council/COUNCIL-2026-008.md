## 1. Executive Summary & Intent

By unanimous decree of the High Sovereign Grand Council, the **Universal Post-Test Telemetry Synchronization Protocol** is hereby established as a mandatory continuous operating standard.

### The Problem Solved: Eliminating Telemetry Drift & Stale Rehearsal Blockers
In distributed multi-repository architectures, local edge rehearsals and developmental experiments frequently record temporary blockers (such as *"awaiting deployment credentials"* or *"migration rehearsal sequence lock"*) into `docs/control-plane/telemetry.json`. When production releases and CI test suites succeed, failure to immediately update edge telemetry causes the central Executive Mission Control dashboard to display stale, contradictory statuses (e.g. displaying *"Vercel Preview"* instead of *"Vercel Prod"*).

### The Invariant Standard
On every successful PR push or commit to any repository in the ChurchCore ecosystem, after all automated testing is accepted (`npm test` / `vitest` / `unittest`), each application repository **MUST execute its telemetry reporting script**:

```bash
python3 scripts/report-telemetry.py --auto
```

Or explicitly record with verified parameters:
```bash
python3 scripts/report-telemetry.py \
  --online true \
  --vercel-url "https://<canonical-domain>" \
  --phase production \
  --completion 100 \
  --supabase-status connected \
  --summary "Production release verified live on Vercel edge and custom domain"
```

## 2. Technical Requirements

### REQ-008-01: Universal Post-Test Telemetry Synchronization Mandate
Every repository must wire telemetry reporting into its automated test lifecycle via `package.json`:
- `"telemetry:report": "python3 scripts/report-telemetry.py --auto"`
- `"posttest": "python3 scripts/report-telemetry.py --auto || true"`
- Chain into `"verify"` commands: `npm run verify` must execute `npm run telemetry:report`.
* **Verification:** `telemetry:report` defined in `package.json` across all fleet repositories and executing cleanly upon test pass.

### REQ-008-02: Autonomous Live Endpoint Probing & Blocker Clearance
The edge `report-telemetry.py` engine shall actively probe the repository's canonical production URL via HTTP HEAD/GET. If an active HTTP response (200, 301, 302, 307, 308) is received:
1. `is_online` is automatically set to `true`.
2. `vercel_status` is automatically set to `"deployed"`.
3. Live production domain is preserved in `custom_domain` and `vercel_url`.

A reachable URL proves availability, not readiness: the probe never sets `readiness_score_pct`, `completion_pct` or `phase`, and never clears `blockers`. Those come only from the edge repository's canonical plan (amended 2026-10-20 on FaithFull Scholars' challenge, `docs/council/CHALLENGE-2026-10-20-faithfull-scholars.md`).
* **Verification:** `python3 scripts/report-telemetry.py --auto` exits with code 0 and records `ONLINE` status.
